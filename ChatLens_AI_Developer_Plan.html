1. System Architecture & Tech Stack

ChatLens AI is engineered as a decoupled single-page application (SPA) with a high-performance Python FastAPI backend, backed by PostgreSQL with vector capabilities and dual AI integrations.

ComponentTechnologyImplementation Detail
Frontend SPA React 18 + Vite Vanilla CSS design system, Recharts for analytics, React Force Graph for Knowledge Graph visualization.
Backend Framework FastAPI + Uvicorn Asynchronous API handling, Pydantic validation, CORS enabled.
Database PostgreSQL + pgvector Single unified database for relational metadata (users, entities, chats) and vector embeddings.
RAG Retrieval Layer LlamaIndex Handles document ingestion, hierarchical chunking, auto-merging retrieval, and embedding generation.
RAG Orchestration LangGraph Manages stateful multi-turn agent execution, tool routing, and cross-chat memory retrieval.
AI Models Gemini 1.5 Pro + GPT-4o Gemini for long-context (1M window) summarization; GPT-4o for natural Q&A and narrative generation.

2. Production Database Schema (PostgreSQL + pgvector)

The system utilizes a single PostgreSQL instance for both structured entity relational tables and pgvector vector search.

-- Enable pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Chats Table
CREATE TABLE chats (
    chat_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    filename VARCHAR(255) NOT NULL,
    group_name VARCHAR(255),
    total_messages INT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Messages Table
CREATE TABLE messages (
    message_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    chat_id UUID REFERENCES chats(chat_id) ON DELETE CASCADE,
    sender VARCHAR(255),
    timestamp TIMESTAMP WITH TIME ZONE NOT NULL,
    content TEXT NOT NULL,
    message_type VARCHAR(50) DEFAULT 'text',
    is_system BOOLEAN DEFAULT FALSE,
    message_hash VARCHAR(64) UNIQUE NOT NULL
);

-- Vector Embeddings Table (pgvector)
CREATE TABLE message_embeddings (
    embedding_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    message_id UUID REFERENCES messages(message_id) ON DELETE CASCADE,
    chat_id UUID REFERENCES chats(chat_id) ON DELETE CASCADE,
    embedding vector(768), -- Gemini text-embedding-004 dimension
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX ON message_embeddings USING hnsw (embedding vector_cosine_ops);

3. WhatsApp Parsing & Deduplication Engine

The parser handles standard and non-standard WhatsApp exports across 4 timestamp patterns, multi-line strings, and Indian scripts (Unicode UTF-8).

Regex Pattern Matcher

# Python Regex matching 4 timestamp formats:
# 1. [DD/MM/YYYY, HH:MM:SS] Sender: Content
# 2. DD/MM/YYYY, HH:MM - Sender: Content
# 3. MM/DD/YY, HH:MM AM/PM - Sender: Content
# 4. [DD/MM/YY, HH:MM:SS] Sender: Content

date_time_pattern = re.compile(
    r'^(?:\[(\d{1,2}[\./-]\d{1,2}[\./-]\d{2,4}), (\d{1,2}:\d{2}(?::\d{2})?(?: ?[APMampm]{2})?)\] |'
    r'(\d{1,2}[\./-]\d{1,2}[\./-]\d{2,4}), (\d{1,2}:\d{2}(?::\d{2})?(?: ?[APMampm]{2})?) - )(.*)'
)

Deduplication & Overlap Logic

Hash Strategy: Every message gets a SHA-256 hash computed from timestamp + sender + content.

During 500-message chunking with 50-message overlaps, identical messages match the message_hash constraint in PostgreSQL and are ignored. Zero message loss and zero duplicates guaranteed.

4. LlamaIndex + LangGraph RAG System

The RAG pipeline provides continuous memory learning across chats.

# RAG Pipeline Flow:
# 1. Ingestion: LlamaIndex reads messages -> splits into chunks -> generates Gemini Embeddings
# 2. Storage: Vectors stored in pgvector table
# 3. Retrieval: Query triggers LlamaIndex AutoMergingRetriever to fetch relevant context
# 4. Orchestration: LangGraph agent passes context to GPT-4o / Gemini for structured response

from llama_index.core import VectorStoreIndex
from llama_index.vector_stores.postgres import PGVectorStore

vector_store = PGVectorStore.from_params(
    database="chatlens",
    host="localhost",
    password="password",
    port=5432,
    user="postgres",
    table_name="message_embeddings",
    embed_dim=768
)

5. Windows Server Production Deployment

ChatLens AI is configured for native deployment on Windows Server using IIS / Nginx and NSSM (Non-Sucking Service Manager).

  1. PostgreSQL Setup: Install PostgreSQL 16 on Windows Server, enable pgvector extension.
  2. Backend Process Management: Register Uvicorn server as a Windows Service using nssm: 
    nssm install ChatLensBackend "C:\Python311\Scripts\uvicorn.exe" "main:app --host 127.0.0.1 --port 8000 --workers 4"
  3. Frontend Production Build: Run npm run build to produce static assets in /dist, served via IIS or Nginx.
  4. Reverse Proxy: Configure Nginx/IIS to proxy /api/* to http://127.0.0.1:8000.
